Building AI with AI

A visual, hands-on book about building software that uses a language model, and about using an AI assistant to help build it. Each chapter pairs a page of diagrams and plain explanation with a notebook you can run in your browser.

📖 Chapters as they are published
🐍 Notebooks that run in Colab
🔁 Recorded model calls that need no key

A language model will answer almost anything you send it. Building something dependable on top of one takes established engineering discipline, adapted for a component whose output can change from one call to the next. This book teaches that discipline with a picture for every idea and code you can run.

1

What the book will cover

The chapters follow the order in which a working system comes together. They start with a single call to a model and what comes back from it, then set up Claude Code, which generates the Python, the back ends, the front ends and the agentic assets in every chapter after that. Later chapters treat a prompt as code, score outputs with evals against expected outcomes, and ground a model in documents with retrieval-augmented generation (RAG). The middle of the book designs agent systems: memory and state, the harness that lets a model act, skills, MCP servers and clients, multi-agent systems directed by a manager agent, agent-to-agent communication over A2A, open-source frameworks such as LangChain and LangGraph, and the clients users reach agents from, such as Claude, Gemini, Slack and Microsoft Teams. The last parts cover data, model choice, security and running a system in production, and six capstones build complete systems with Claude Code.

Where a chapter needs statistics, such as a confidence interval around an evaluation score, it links to the chapter of the first book that explains it. Where it leans on Python or a library, such as calling a web API, writing tests or shaping a table with pandas, it links to the guide in Python, Visually that teaches it.

How the book uses Claude Code

From Chapter 2 on, the code a chapter needs is written by Claude Code, Anthropic's coding assistant, and every chapter ends its explanation with a section headed Build it with Claude Code that shows how. Claude Code works inside a project's folder. You start it in a terminal with the claude command, or in an IDE, the desktop app or at claude.ai/code, and give it a prompt. It reads the project's files, runs commands such as the test suite, and creates or edits files, asking for permission according to its settings. You review what it changed and decide what to keep. The command claude -p runs the same kind of session without an interactive screen. It takes the prompt, works until it is done and prints what it did, which is how the book runs its builds (Claude Code 2.1.322, as of November 2026).

A session is steered by files written in Markdown, the plain-text format that the .md ending names. Claude Code treats one of them specially, and the others are files the book writes for each build.

FileWhat it holds
CLAUDE.mdWritten by the project's developers. Standing instructions Claude Code reads at the start of every session in the project: how to build and test, conventions, rules that always apply. This book's repository has one.
spec.mdWritten by the developer before any code. What to build, in plain words: each function, its inputs and outputs, the edge cases and what the code must not do. The name is the book's convention, and Claude Code reads it like any other file.
tests/Written by the developer before any code. The same requirements as executable pytest tests. They decide when the work is done, and Claude Code runs them itself.
prompt.mdThe exact prompt the session starts from. In an interactive session you would type it, and the book keeps it in a file so every build has a record of it.
transcript.jsonWritten by the book's build script. Every step Claude Code took, its tool calls and their results, with the version, model, date, cost and test result.

Prompting a coding assistant works best when the prompt is short and the files carry the detail. This is the prompt Chapter 1's build used.

prompt.md
Read spec.md and write triage.py so that every test in tests/ passes. Create and change files with the Edit tool. The only shell command you may run is python3 -m pytest -q tests, which runs the tests. Do not change the tests.

It points to the spec in place of restating it, defines done as the tests passing, names the tools and the one command allowed, and puts the tests out of reach, because a test the assistant could edit would decide nothing. What the code should do lives in spec.md, written the way a developer would brief a colleague, and the tests turn each sentence of it into a check. A gap in the spec shows up as a case the tests don't cover, and Claude Code reported one in Chapter 2's build on its own. Each chapter's build section shows its prompt, walks through its spec and tests, and reports what Claude Code did and what review changed.

The book's builds run with a flag, --bare, under which Claude Code skips CLAUDE.md, hooks and plugins, and the build script gives each session an empty home folder of its own. Everything a build relies on is in its prompt, spec and tests, so anyone can repeat it. Each build's files are in the repository's builds/ folder, and python3 scripts/claude_build.py <chapter-slug> --out my-build runs it again with your own Claude Code account. Running Claude Code needs a Claude account or an Anthropic API key, and the notebooks don't, because they import the code each build generated. Later parts return to these files: Part 2 covers working with Claude Code in depth, and Part 10 covers skill files, which package a reusable procedure for an agent.

Notebooks that call a model

The tickets, documents and other records the examples work on are written for the book and describe no real organization or person. Most notebooks send requests to a language model through Anthropic's Python library. A live call needs an API key and returns a slightly different answer each time, which would make the book's numbers impossible to check, so every notebook can run in either of two modes.

🔁

Replay by default

The notebook answers each request from a recording kept in the book's repository. It needs no key, makes no network call and prints the same thing on every run, so the page and the notebook always agree. The notebook names the model and the date each recording came from.

⚡

Live calls with your own key

One switch at the top of the notebook sends the same requests to the real API with your own key, kept in Colab's secrets panel. The answers will differ from the recorded ones, and the cost of the calls is billed to your account.

What helps before you start

The book assumes you write Python and have worked in a notebook. For a refresher, the free library Python, Visually covers both from the beginning, starting with its guide Python from the Start. No background in machine learning is assumed, and each chapter explains the model concepts it relies on.
